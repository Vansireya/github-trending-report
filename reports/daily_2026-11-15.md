# 给编码代理补上评审、浏览器与协议层

今天榜单几乎被“怎么让编码代理更好用”占满：Plannotator 把代理产出的计划、HTML 和 diff 变成可批注的评审面，Chrome DevTools MCP 则让代理直接操作真实浏览器。前者补的是人机来回，后者补的是代理的眼睛和手。


### backnotprop/plannotator

**一句话概括**：本地浏览器里的代理评审台，把计划、HTML 产物和代码 diff 摊开批注，一键把反馈送回代理。

**详细介绍**：代理提出方案或改完代码后，人往往只能在终端里读文本、再手打反馈。它通过插件和钩子把产物拉到浏览器里标记、评论，适合多代理并行时集中处理决策和 PR 评审；局限是依赖各代理的接入方式，且浏览器端暴露内容需注意隐私。

**项目网址**：https://github.com/backnotprop/plannotator

**Star 数量**：11,254


### GoogleChrome/modern-web-guidance-src

**一句话概括**：把现代 Web 平台最佳实践和兼容数据做成代理技能，专门纠正模型爱写旧模式的老毛病。

**详细介绍**：编码代理的训练数据里堆满旧代码，容易为原生已支持的能力生成臃肿 JS。这套技能由 Chrome、Edge、Firefox 和 MDN 团队共同维护，直接嵌入代理工作流；目前是源仓库，重点在内容编写与评估，不是开箱即用的产品。

**项目网址**：https://github.com/GoogleChrome/modern-web-guidance-src

**Star 数量**：6,198


### tradermonty/claude-trading-skills

**一句话概括**：面向个人投资者的 Claude 交易工作流技能包，管市场复盘、风险管理和交易日志，不替你做买卖决定。

**详细介绍**：作者明确说目标不是让 AI 下单，而是把复盘、计划、记录这些容易偷懒的环节结构化。适合以 ETF 和股息股为主、偶尔波段的人；但它是流程工具，不提供信号，也不承诺收益，README 自带免责声明。

**项目网址**：https://github.com/tradermonty/claude-trading-skills

**Star 数量**：4,919


### ChromeDevTools/chrome-devtools-mcp

**一句话概括**：把 Chrome DevTools 包成 MCP 服务器和 CLI，让编码代理能录制性能 trace、查网络请求和控制实时浏览器。

**详细介绍**：代理调试前端时常靠猜，这个项目让它直接读控制台、截图、分析网络并做可靠自动化。功能很实在，但 README 也提醒：它会把浏览器实例内容暴露给 MCP 客户端，共享敏感数据的环境要谨慎。

**项目网址**：https://github.com/ChromeDevTools/chrome-devtools-mcp

**Star 数量**：56,385


### alibaba/open-code-review

**一句话概括**：阿里内部打磨两年的 AI 代码评审 CLI，确定性流水线加 LLM Agent，输出行级评论。

**详细介绍**：它不只读 diff，还能让代理翻全文、搜代码库、看其他改动文件来补上下文，适合仓库级评审和审计陌生代码。内置多语言规则集覆盖 NPE、线程安全、XSS 等；基准称同模型下比通用代理精度更高、token 消耗约九分之一，但需自配模型端点。

**项目网址**：https://github.com/alibaba/open-code-review

**Star 数量**：51,510


### QwenLM/qwen-code

**一句话概括**：Qwen 系的终端编码代理，1.0 预览把 Qoder 的 agent harness 并了进来，还延伸到 IDE、桌面和聊天工具。

**详细介绍**：卖点是开箱即用的 Agentic 能力：Auto-Memory、Skills、SubAgents、MCP 首会话就能用，并支持 OpenAI、Anthropic、Gemini 和本地模型运行时切换。项目自称正用自身代理提 issue、跑测试，这种自举值得观察，但也意味着迭代节奏可能很猛。

**项目网址**：https://github.com/QwenLM/qwen-code

**Star 数量**：30,396


### dream-num/univer

**一句话概括**：开源 Office SDK，从表格和文档编辑起步，想把计算、协作和文件处理嵌进你自己的产品与代理。

**详细介绍**：适合需要在应用里内置类 Excel/Word 编辑能力、又不想被 Office 365 绑死的团队。它提供 Facade API 和事件机制连接应用与代理，架构上强调功能边界和跨功能撤销重做；但完整 Office SDK 能力涉及许可范围，采用前要看清授权。

**项目网址**：https://github.com/dream-num/univer

**Star 数量**：25,006


### ag-ui-protocol/ag-ui

**一句话概括**：一个轻量的事件式协议，标准化 AI 代理如何把执行过程流向前端应用并接收用户输入。

**详细介绍**：代理后端按约 16 种标准事件类型发消息，前端用少量兼容输入回传，中间件负责适配 SSE 等不同传输。它解决的是代理与 UI 之间各写各的胶水代码问题；协议本身不绑定框架，价值取决于有多少集成方跟进。

**项目网址**：https://github.com/ag-ui-protocol/ag-ui

**Star 数量**：17,421


### ashhart/TensorFold

**一句话概括**：用 Zig 写的 LLM 推理引擎，直接在 Apple Silicon 和 NVIDIA GPU 上跑 Metal 或 CUDA 内核。

**详细介绍**：它读 checkpoint、分词、跑内核一条龙，服务时不需要 Python 或 MLX 环境，对想减少运行时依赖的人有吸引力。项目还引入 Agent Traffic Control 来协调代理贡献者避免重复劳动，这种协作方式本身比引擎更少见；成熟度仍需观察。

**项目网址**：https://github.com/ashhart/TensorFold

**Star 数量**：2,183


### JuliusBrussee/caveman

**一句话概括**：让编码代理“像穴居人说话”的提示技能加代理，号称靠少读少写砍掉大量 token。

**详细介绍**：思路是压缩代理的输入输出表达，同时保持代码精确，README 列了与 Claude Code、Codex 的对比数据，并称被 Adobe Research 引用、JetBrains 做过 A/B。争议点也明显：省 token 的代价是表达退化，复杂任务里是否稳定，需要自己拿任务验证。

**项目网址**：https://github.com/JuliusBrussee/caveman

**Star 数量**：120,129


**今日总结**：今天最值得看的是代理工具开始分层：有人做评审面，有人做浏览器接口，有人做交互协议。省 token 的噱头很响，但真正决定代理好不好用的，还是这些中间层是否扎实。
