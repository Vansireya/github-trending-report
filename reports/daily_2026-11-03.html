AI代理开始接管桌面与记忆，本地推理继续下沉

今天榜单被AI代理基础设施占据：一边是让代理直接操作桌面应用的agent-desktop，另一边是给代理装上跨会话记忆的claude-mem。同时，FreeToken和colibri把MoE大模型往个人硬件上推，方向很一致——让代理和模型都更贴近本地。

1
vercel-labs/agent-desktop ★ 10,444
Rust

用操作系统无障碍树让AI代理读写桌面应用，不靠像素匹配，每次操作后重新快照确认。

代理通过CLI调用获取元素快照，按ref执行操作再快照验证，循环留在代理侧。局限在于快照、剪贴板和截图可能含隐私内容，需自行隔离日志；JEV辅助功能还会把屏幕描述发给模型提供商。

2
thedotmack/claude-mem ★ 110,955
TypeScript

给Claude Code等代理做跨会话记忆压缩，自动捕获工具使用观察并生成语义摘要，下次会话再注入。

适合长期项目里代理反复失忆的场景。它依赖宿主钩子或聊天日志来捕获行为，不同代理的接入方式不一；记忆压缩的质量和隐私边界需要使用者自己把关。

3
D4Vinci/Scrapling ★ 93,212
Python

Python爬虫框架把快速HTTP、隐身浏览器、解析和并发爬取塞进一个库，还能通过MCP给AI代理用。

从单次请求到全站爬取都覆盖，支持Cloudflare Turnstile处理、代理轮换和断点续爬。功能面很宽，但隐身浏览器和反反爬能力在实际站点上的效果仍需按目标站点验证。

4
hyprwm/Hyprland ★ 40,029
C++

完全独立的动态平铺Wayland合成器，不依赖wlroots，动画、模糊、插件和即时配置重载都自己实现。

适合想要好看且高度可定制的Wayland桌面用户。独立代码库意味着不跟随wlroots生态，部分Wayland协议和显卡驱动兼容性需要自己踩坑，但插件体系和撕裂支持对游戏场景有实际价值。

5
Donchitos/Claude-Code-Game-Studios ★ 33,781
Shell

把Claude Code会话改造成49个代理组成的游戏工作室，有总监、部门主管和 specialists，带质量门禁。

针对单人用AI做游戏时缺乏设计评审和QA的问题，用角色分工和升级路径来补结构。它产出的是流程和文档约束，不是游戏本身；代理数量多，协调开销和提示词维护成本不低。

6
FlashML-org/FreeToken ★ 16,214
Python

面向消费硬件的MoE推理引擎，把GPU、CPU和主机内存当成统一弹性平台，在游戏PC上跑290B+模型。

核心是带宽自适应CPU-GPU协同、专家缓存和语义感知KV缓存，减少代理上下文编辑后的重复计算。实际速度取决于内存带宽和磁盘，消费级硬件上跑前沿模型仍是工程折衷。

7
pingdotgg/t3code ★ 42,354
TypeScript

代理控制台，用移动端、Web和Electron桌面端统一操控本机已装好的Claude Code、Codex、Cursor等代理。

适合已经在电脑上配好多个代理CLI、想远程或跨设备查看和操作的人。它本身不卖模型，依赖你已有的订阅和登录；支持列表虽长，但每个提供商的接入深度和体验一致性还需实际使用检验。

8
shiyu-coder/Kronos ★ 46,074
Python

首个开源的金融K线基础模型，用分层离散tokenizer加自回归Transformer处理OHLCV序列。

针对金融数据高噪声特点设计，训练数据来自45+全球交易所，已被AAAI 2026接收。适合量化研究做预训练和微调起点，但金融预测本身的高风险不会因为模型开源而降低。

9
kornia/kornia ★ 12,188
Python

基于PyTorch的可微分计算机视觉库，1200+算子覆盖几何视觉、图像处理和特征匹配。

当手写几何变换或RANSAC变得冗长脆弱时，Kornia提供GPU加速的批量实现。它正在转向可执行规范和一致性测试，API增长放缓，对追求稳定接口的生产项目是好事。

今日结论

代理的记忆、操作界面和本地推理引擎正在同时成熟，今天这几个项目拼在一起，已经能看出个人AI工作站的雏形。值得先试agent-desktop和colibri，一个管操作，一个管模型落地。
