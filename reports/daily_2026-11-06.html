Agent 工具链开始分层：上下文、技能与桌面操控

今天榜单几乎被 Agent 基础设施占满，但真正值得多看一眼的是 NVIDIA/auto-ontology 和 vercel-labs/agent-desktop：前者试图给 Agent 补上企业数据的语义层，后者干脆绕开截图，用操作系统无障碍树让 Agent 操作桌面应用。

1
NVIDIA/auto-ontology ★ 7,665
Python

从企业元数据生成本体，给 Agent 提供可校验、带来源的业务语义上下文层。

Agent 查数据库不难，难的是保证“营收”这类指标在不同系统里定义一致且可追溯。它通过 MCP、CLI 和 API 把本体暴露给任意 Agent 框架，并校验生成查询是否符合已认证定义。局限在于效果高度依赖企业元数据质量。

2
mattpocock/skills ★ 315,535
Shell

一套小而可组合的 Agent 技能，明确反对把工程流程整个交给“氛围编程”。

作者把日常工程中用的技能从 .agents 目录直接开源，强调可适配任意模型、可手动修改。安装方式分插件自更新和复制文件两种，选错会重复安装。适合想保留控制权、又不想从零写提示词的人。

3
garrytan/gstack ★ 140,060
TypeScript

把 Claude Code 包装成虚拟工程团队，23 个斜杠命令分别扮演 CEO、设计、QA 等角色。

每个角色对应一个 Markdown 命令，覆盖产品重想、架构锁定、代码审查、浏览器 QA 和发布。它面向创始人和首次使用 Claude Code 的人，用固定角色替代空白提示词。实际效果取决于命令质量，不是自动化的银弹。

4
Usagi-org/ai-goofish-monitor ★ 17,786
Python

用 Playwright 加 AI 盯闲鱼商品，多任务并发、多账号轮换，还配了完整 Web 后台。

可以按关键词、价格、包邮、区域筛选，并用多模态模型分析商品，通知走 ntfy、企业微信、Bark 等渠道。Docker 一键部署，SQLite 存任务和价格历史。风险在于平台反爬和账号轮换的合规边界。

5
D4Vinci/Scrapling ★ 98,196
Python

把 HTTP 请求、隐身浏览器、解析和并发爬虫塞进一个 Python 库，还带 MCP 服务。

从单次请求到整站抓取都覆盖，支持 Cloudflare Turnstile 处理、代理轮换、暂停恢复和 Markdown 输出。对需要给 Agent 接网页数据的场景很顺手，但隐身浏览器和反反爬能力也意味着使用时要留意目标站点的条款。

6
vercel-labs/agent-desktop ★ 17,150
Rust

不截图、不匹配像素，直接读桌面应用的无障碍树，让 Agent 按元素引用点击输入。

它把可操作元素转成 JSON 并给每个元素一个 ref，Agent 点完再读一次 UI 确认结果。CLI 和 C 库两种形态，循环逻辑留在 Agent 侧。局限是依赖应用的无障碍支持程度，且快照和剪贴板可能泄露隐私内容。

7
max-sixty/worktrunk ★ 11,593
Rust

给 Git worktree 套一层顺手的 CLI，专为并行跑多个 AI Agent 设计。

原生 git worktree 建一个工作区要反复敲分支名，Worktrunk 用三个核心命令把这件事简化到接近分支操作，还带 hooks 和写时复制构建缓存。适合同时管理 5 到 10 个 Agent 任务的人，但仍是本地工作流工具，不解决 Agent 本身的协调问题。

8
lz4/lz4 ★ 12,427
C

老牌极速压缩算法，压缩每秒超过 500 MB，解压能跑到内存带宽。

提供可调加速因子在压缩率和速度之间取舍，另有 LZ4_HC 高压缩版本，解压速度不变。支持字典压缩，适合小文件场景。它不是新项目，出现在榜单里更像基础设施的日常存在感。

9
google/skills ★ 22,457
Python

Google 官方出的 Agent 技能集合，覆盖 Google Cloud 上手、IAM、数据分析和 Agent 部署。

通过 npx 安装，可选择具体技能、目标 Agent 和安装范围，之后还能更新并清理过时技能。内容偏 Google Cloud 生态，对非 GCP 用户价值有限，但官方维护的技能包在一致性上比社区拼凑更可靠。

今日结论

Agent 竞争正从模型转向上下文和操作层：谁能把企业语义、桌面 UI、浏览器和 Git 工作流变成 Agent 可靠可校验的接口，谁就掌握下一段工程体验。
