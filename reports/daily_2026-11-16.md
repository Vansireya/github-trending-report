# 让 Agent 真正干活的协议、技能与审查层

今天的榜单几乎被同一件事占满：把编码 Agent 从聊天框里拽出来，接进真实工作流。最显眼的是 Chrome DevTools 的 MCP 服务器和阿里开源的代码审查工具，前者让 Agent 直接操控浏览器，后者用确定性管线加 LLM 做行级审查，都指向同一个问题——Agent 需要可验证的反馈回路。


### dream-num/univer

**一句话概括**：一套开源的 Office SDK，把表格、文档的编辑与计算能力嵌进你自己的产品，也面向 AI Agent 开放。

**详细介绍**：适合需要在应用里内建电子表格或文档编辑的团队，开源核心提供 Sheets 和 Docs，再通过 Facade API 与事件把编辑能力接给应用或 Agent。局限在于它定位是 SDK 而非成品办公套件，完整协作与文件处理能力要看商业授权范围。

**项目网址**：https://github.com/dream-num/univer

**Star 数量**：26,455


### ag-ui-protocol/ag-ui

**一句话概括**：一个轻量的事件协议，规定 Agent 后端如何向前端应用发事件、收输入，约 16 种标准事件类型。

**详细介绍**：解决的是 Agent 与用户界面之间缺少统一接线的问题：后端按标准事件类型输出执行过程，前端据此渲染状态和交互。中间件层声称兼容任意事件传输，但生态成熟度仍需看各框架集成的实际覆盖。

**项目网址**：https://github.com/ag-ui-protocol/ag-ui

**Star 数量**：18,061


### google-labs-code/stitch-skills

**一句话概括**：Google Stitch 的 Agent 技能与插件集合，遵循 Agent Skills 开放标准，可装进 Codex、Claude Code、Cursor 等编码 Agent。

**详细介绍**：把设计相关能力拆成 stitch-design、stitch-build、stitch-utilities 三组插件，通过插件市场安装。价值取决于你是否在用 Stitch 做设计到代码的流程；OpenCode 需要手动安装，说明跨 Agent 兼容并非开箱即用。

**项目网址**：https://github.com/google-labs-code/stitch-skills

**Star 数量**：9,407


### backnotprop/plannotator

**一句话概括**：本地浏览器里的 Agent 审阅台，把计划、HTML 产物、代码 diff 摊开让你批注，再一键把反馈送回 Agent。

**详细介绍**：针对多 Agent 并行工作时人跟不上节奏的痛点，通过插件和钩子接入 Claude Code、Codex、Gemini CLI 等，Agent 提出方案或完成工作时自动打开页面供标注。本质是人工卡点工具，审阅质量仍取决于人是否真的看。

**项目网址**：https://github.com/backnotprop/plannotator

**Star 数量**：11,978


### ChromeDevTools/chrome-devtools-mcp

**一句话概括**：把 Chrome DevTools 包成 MCP 服务器和 CLI，让编码 Agent 控制并检查一个活的 Chrome 浏览器。

**详细介绍**：Agent 可以录性能 trace、分析网络请求、截图、读控制台报错并带 source map 栈，用 Puppeteer 做可靠自动化。真正值得注意的是它给了 Agent 可观测的浏览器反馈，而不只是盲写代码；代价是浏览器内容会暴露给 MCP 客户端，敏感数据场景要谨慎。

**项目网址**：https://github.com/ChromeDevTools/chrome-devtools-mcp

**Star 数量**：57,124


### alibaba/open-code-review

**一句话概括**：阿里内部打磨两年的 AI 代码审查 CLI，确定性管线加 LLM Agent，输出行级精确的审查评论。

**详细介绍**：读 Git diff 后由带工具调用的 Agent 读全文、搜代码库、看其他改动文件来补充上下文，内置 NPE、线程安全、XSS、SQL 注入等多语言规则集。README 称同等模型下精度和 F1 显著高于通用 Agent 且 token 消耗约为其九分之一，但这是自报基准，需自行验证。

**项目网址**：https://github.com/alibaba/open-code-review

**Star 数量**：52,278


### Tencent/LoopForge

**一句话概括**：腾讯开源自托管工作台，用聊天机器人加 SOP 编排 CodeBuddy、Codex、Claude Code 等编码 Agent 交付软件。

**详细介绍**：向 Main Bot 描述需求，它开 Docker 沙箱、检出仓库、分派角色并开 PR；跑通一次的流程可固化为带人工审批门的 SOP。思路是把 Agent 交付变成可重复的流水线，但前提是你愿意维护沙箱、角色和审批环节这套基础设施。

**项目网址**：https://github.com/Tencent/LoopForge

**Star 数量**：1,727


### ggml-org/ggml

**一句话概括**：无依赖的纯 C/C++ 张量库，跨 x86、ARM、RISC-V 到 WebAssembly，支持 2 到 8 位整数量化。

**详细介绍**：定位是极简、可移植的机器学习底层，SIMD 优化内核覆盖主流架构，后端包括 CPU、GPU、NPU 和浏览器，运行时零内存分配。它是 llama.cpp 等地基型项目的基础，本身不提供模型或应用；核心改动要求提到 llama.cpp 提 PR，说明其开发节奏与下游绑定。

**项目网址**：https://github.com/ggml-org/ggml

**Star 数量**：15,965


### elementalsouls/Claude-BugHunter

**一句话概括**：给 Claude Code 装的漏洞挖掘技能包，83 个技能、15 个斜杠命令，外加 681 条公开报告模式。

**详细介绍**：把方法论、Web 应用狩猎、企业身份与基础设施攻击矩阵分层打包，并集成 Burp MCP，目标是让 Claude Code 按资深红队研究员的套路工作且不越范围。适合授权测试和靶场练习，但技能包再全也替代不了对目标业务的理解，误报和越界风险仍需人把关。

**项目网址**：https://github.com/elementalsouls/Claude-BugHunter

**Star 数量**：6,623


### GoogleChrome/modern-web-guidance-src

**一句话概括**：Chrome、Edge、Firefox 与 MDN 共同维护的技能集，把现代 Web 平台最佳实践和兼容数据塞进编码 Agent。

**详细介绍**：针对编码 Agent 因训练数据偏旧而默认生成过时模式的问题，用技能引导它改用原生、高性能的 Web 平台方案。由四大浏览器团队共同维护是它可信度的来源，但效果取决于 Agent 是否真的遵循技能而非凭记忆写代码。

**项目网址**：https://github.com/GoogleChrome/modern-web-guidance-src

**Star 数量**：7,356


**今日总结**：今天的主线不是又一个 Agent 框架，而是给 Agent 装仪表盘和刹车：浏览器可观测、审查可定位、交付有审批门。谁先把反馈回路做扎实，谁才谈得上可靠。
