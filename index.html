AI 编码工具开始补设计课，也开始学会组队

今天值得看的不是又多了几个 Agent，而是围绕它们的“职业培训”突然成套出现了：有人教它们做不丑的页面，有人逼它们先想清楚再写代码，还有人给多代理协作配上独立工位。AI 编码的竞争，正在从“会不会写”移到“能不能稳定地把活做好”。

1
elayadesign/ai-design-skills ★ 9,678

把落地页设计规则装进 Claude Code、Cursor 和 Codex 的技能包。

目前的核心技能会先问需求，再处理页面结构、转化文案、字体、间距、圆角和动效。它还是一个刚起步的合集，但方向很实在：把设计师脑中的判断，整理成编码代理能执行的规则。

2
Nutlope/hallmark ★ 39,226
CSS

不只教 AI 怎么设计，还让浏览器替它抓出页面里的“机器味”。

Hallmark 会从主题库里组合视觉方向，再检查对比度、焦点、动效，以及那些一眼就像 AI 模板的惯用套路，最后还安排独立上下文复审。它解决的不是“能不能生成页面”，而是“生成后敢不敢直接交付”。

3
nightly-labs/openbot ★ 2,566
TypeScript

给多位 AI 代理分工位、排队列、传文件的本地桌面工作区。

Codex、Claude、Grok 等代理可以拥有各自的工作区和对话，同时共享任务、文件、浏览器与代理间消息。需要特别留意的是，它仍处于开发预览阶段，当前代理以高权限运行；能力很强，安全边界也必须自己看紧。

4
obra/superpowers ★ 306,558
Shell

一套会先逼编码代理想清需求，再允许它动手写代码的开发方法论。

它用可组合的 skills 和启动指令约束代理流程，先澄清目标、形成规格，再进入实现。与其继续给模型堆提示词，它更像是在给 AI 工程师制定团队工作制度。

5
pbakaus/impeccable ★ 90,770
Rust

用 polish、bolder、critique 和 audit 给编码代理补一套设计词汇。

它不换模型，而是改变代理观察和评价界面的方式：需要更大胆时怎么说，交付前如何批评和审计，怎样识别模板化的 AI 设计。适合已经能生成页面，却总觉得成品“哪儿都对、就是没味道”的场景。

6
makecindy/cindy ★ 7,583
TypeScript

把多台电脑和手机接成同一位 AI 助手的开源桌面 Agent。

你可以换设备继续同一个会话、访问原来的文件，甚至复用另一台电脑上的模型配置；手机端还带远程桌面。它想解决的不是“再造一个聊天框”，而是让 AI 助手真正跨设备跟着你的工作走。

7
gitroomhq/postiz-app ★ 39,490
TypeScript

能自托管的社交媒体排程台，也给 AI Agent 留好了发布入口。

Postiz 把内容排程、自动发布和效果分析放在一起，既有托管版本，也能部署到自己的服务器。它还提供 API 和自动化集成，适合让 Agent 参与内容流水线，而不是每天手动复制、粘贴、点发布。

8
affaan-m/ECC ★ 290,997
JavaScript

把技能、记忆、安全和“先研究再动手”的流程打包给编码代理。

ECC 面向 Claude Code、Codex、Cursor 等工具，试图把零散的 Agent 调优经验整理成一套可安装的工作系统。它的看点不在某条神奇提示词，而在于开始把代理性能当成一项需要持续管理的工程。

9
HKUDS/DeepTutor ★ 46,207
Python

不满足于答完一道题，而是想长期维护学习路径、评估和辅导记忆。

DeepTutor 把学习工作区、分块笔记、讲解视频、评估和可恢复的知识索引放进同一套系统。它瞄准的是持续辅导，而不是“问一次、答一次”的临时学习助手。

今日结论

今天最值得记住的，不是某个 Agent 又多会了一招，而是大家开始认真给它们补流程、审美、记忆和边界。模型像员工，skills 与工作区正在变成真正决定产出的管理制度；OpenBot 这类高权限预览版也提醒我们，能力越强，护栏越不能省。
